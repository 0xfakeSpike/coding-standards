# Python testing

For test strategy, see [testing-strategy.md](../../general/testing-strategy.md). This document covers only Python tools and practices.

## Framework

### Use pytest [Recommended]

Write tests as plain functions with `assert`. Do not inherit from `unittest.TestCase`. Database tests in Django projects may use the framework's own `TestCase`.

**Source:** pytest Docs

### Enable strict mode [Recommended]

Put the configuration in `pyproject.toml` and enable `strict`. New projects use the `importlib` import mode.

**Why:** Misspelled markers are silently accepted, and nobody finds out when a test marked `xfail` unexpectedly passes.

**Example:**

```toml
[tool.pytest]
minversion = "9.0"
testpaths = ["tests"]
addopts = ["--import-mode=importlib"]
strict = true
```

**Exceptions:** Below pytest 9.0, use `[tool.pytest.ini_options]` and set `--strict-markers` and `xfail_strict` separately.

**Source:** pytest Docs

## Organization

### Keep tests outside the package and mirror its structure [Recommended]

The structure of `tests/` follows `src/`. Name files `test_*.py` and functions `test_<behavior>_<condition>`.

**Source:** pytest Docs, Google Python Style Guide

### Prepare dependencies with fixtures [Recommended]

Write shared setup as fixtures in `conftest.py`. When cleanup is needed, use `yield` and put the cleanup code after it. Do not share state between tests through module-level variables. Write files generated by tests to `tmp_path`, not the repository directory.

**Example:**

```python
@pytest.fixture
def account(db: Database) -> Iterator[Account]:
    created = db.create_account()
    yield created
    db.delete_account(created.id)
```

**Source:** pytest Docs

### Start with the narrowest fixture scope [Recommended]

Default to `function` scope. Use `module` or `session` only for resources that are expensive to create and whose content is not modified. Use `autouse=True` only for setup that all tests need. Otherwise, the dependencies are invisible.

**Source:** pytest Docs

### State the type in exception assertions [Recommended]

Use `pytest.raises(SpecificType)` with only one statement in the block, and assert on exception attributes for the information you need. Messages are not a stable interface: use `match=` to tell exceptions apart only for broad types such as `ValueError`. Do not assert `Exception`. Compare floats with `pytest.approx`.

**Example:**

```python
def test_withdraw_rejects_overdraft(account: Account) -> None:
    with pytest.raises(InsufficientFundsError) as exc_info:
        account.withdraw(Decimal("100"))
    assert exc_info.value.shortfall == Decimal("20")
```

**Tooling:** `PT011`, `PT012`, `B017`.

**Source:** pytest Docs, Ruff Docs

## Parametrization

### Use parametrize for multiple inputs [Recommended]

For multiple inputs to the same behavior, use `@pytest.mark.parametrize`, not a loop in the test. Write an `id` when the data does not explain itself. For an expected failure in a single test case, use `marks=pytest.mark.xfail`.

**Why:** Each input reports its result independently, and one failure does not stop the others from running.

**Example:**

```python
@pytest.mark.parametrize(
    ("amount", "expected"),
    [
        pytest.param(9999, 800, id="below-free-threshold"),
        pytest.param(10000, 0, id="at-free-threshold"),
    ],
)
def test_shipping_fee(amount: int, expected: int) -> None:
    assert calculate_shipping_fee(amount) == expected
```

**Tooling:** `PT006`, `PT007`.

**Source:** pytest Docs

## Test doubles

### Use monkeypatch for environment and attributes [Recommended]

Use `monkeypatch` to change environment variables, dict items, and attributes. It restores them automatically when the test ends. Do not assign to `os.environ` directly.

**Source:** pytest Docs

### Mocks must have a spec [Recommended]

Use `create_autospec` or `patch(..., autospec=True)`, not a bare `Mock()`.

**Why:** A bare mock accepts any method and arguments, so tests pass even when the code under test makes the wrong call.

**Example:**

Avoid:

```python
gateway = Mock()
```

Prefer:

```python
gateway = create_autospec(PaymentGateway, instance=True)
```

**Source:** Python Standard Library Docs

### Patch where the name is used [Recommended]

The target of `patch` is the place where the name is looked up. If `orders.py` has `from gateway import charge`, patch `orders.charge`, not `gateway.charge`.

**Source:** Python Standard Library Docs

### Prefer injecting test doubles [Recommended]

When a dependency is passed as a parameter, pass a fake implementation that satisfies the `Protocol` directly. This is simpler than patching and does not bind to internal module paths.

### Control time through injection [Recommended]

Code that needs controllable time takes a parameter such as `now: Callable[[], datetime]`. Tests pass a fixed clock. Do not write real `time.sleep` waits.

## Integration tests

### Separate integration tests with a marker [Recommended]

Mark integration tests with `@pytest.mark.integration` and register the marker in configuration. At commit time, you may skip them with `pytest -m "not integration"`. Before merging, the full suite must run.

**Source:** pytest Docs

### Verify SQL and protocols against real dependencies [Recommended]

Integration tests for databases and message queues connect to real services. Do not mock SQL. Run each test in a transaction and roll it back, or use a separate database.

### Use pytest-asyncio or anyio for async tests [Recommended]

`pytest-asyncio` defaults to strict mode, so tests need `@pytest.mark.asyncio`. Projects that are entirely async may set `asyncio_mode = "auto"`. FastAPI projects may use `@pytest.mark.anyio`.

**Source:** pytest-asyncio Docs, FastAPI Docs

## Benchmarks

### Measure with pytest-benchmark [Recommended]

Do not base performance assertions on hand-written timing. Measure with the `benchmark` fixture and validate the return value. Keep benchmarks in a separate directory and run them in a fixed environment. Save results with `--benchmark-autosave` and compare with the last run using `--benchmark-compare`.

**Example:**

```python
def test_parse_invoice_speed(benchmark: BenchmarkFixture) -> None:
    result = benchmark(parse_invoice, SAMPLE_INVOICE)
    assert result.total == Decimal("120.00")
```

**Source:** pytest-benchmark Docs
