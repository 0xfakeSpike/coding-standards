# 国际化

本文规定文案管理、复数、日期和货币、时区、RTL 和文案长度。`hreflang` 见 [html.md](html.md)。只有一种语言的项目，日期格式、时区和数字格式的规则同样适用。

## 文案管理

### 界面文案不写死 【推荐】

需要翻译的项目，界面文字全部走消息文件或消息 API，包括 `aria-label`、`alt`、`placeholder`。

**工具：** `formatjs/no-literal-string-in-jsx`。

**来源：** FormatJS 文档

### 一条消息是完整的句子 【推荐】

不用字符串拼接组句。值在开发时已知时，写成多条完整消息。插值只用于运行时才知道的值，比如用户名和时间。

**原因：** 语序和词形随语言变化，译者无法调整代码里拼好的片段。

**示例：**

反例：

```ts
const text = t('deleted') + count + t('files');
```

正例：

```ts
const text = t('files_deleted', { count });
```

**工具：** `formatjs/prefer-full-sentence`。

**来源：** ICU 消息格式文档、i18next 文档

### 键和参数有语义，并提供上下文 【推荐】

键写用途，比如 `checkout.submit`，不把原文当键。参数用 `{guestCount}` 这样的名字，不用 `{0}`。FormatJS 项目把 `defaultMessage` 和 `description` 写在使用处。

**工具：** `formatjs/enforce-description`、`formatjs/no-invalid-icu`。

**来源：** i18next 文档、FormatJS 文档、ICU 消息格式文档

### 不关闭插值转义 【必须】

i18next 默认转义插值。不用 `escapeValue: false` 或 `{{- value}}` 处理用户输入，确需关闭时自行转义。安全要求见 [security.md](security.md)。

**来源：** i18next 文档

### 语言标签用 BCP 47 【推荐】

只在需要区分时加地区，比如 `en-GB`。初次访问用 `Accept-Language` 选择，不用 IP 推断。

**来源：** W3C 语言协商说明、W3C 语言标签说明、MDN

## ICU 复数

### 复数用消息语法，不用条件分支 【推荐】

用 ICU 的 `plural`，`other` 分支必填，数字用 `#`。只为某个精确值定制时用 `=0`。不用 `=1` 代替 `one`，有些语言的 `one` 不只对应 1。序数用 `selectordinal`。ASCII 单引号是转义符，展示文字里的撇号用 `’`。

**原因：** 各语言的复数类别不同。英语两种，阿拉伯语六种，中文只有 `other`。代码里写 `count === 1` 只对部分语言成立。

**示例：**

```text
{count, plural, =0 {No files} one {# file} other {# files}}
```

**工具：** `formatjs/enforce-plural-rules`、`formatjs/prefer-pound-in-plural`。

**来源：** FormatJS 文档、ICU 消息格式文档、MDN

### `select` 在外，`plural` 在内 【推荐】

每个分支写完整的句子，嵌套尽量不超过一层。

**工具：** `formatjs/no-multiple-plurals`。

**来源：** ICU 消息格式文档

### i18next 用后缀表达复数 【必须】

键写 `file_one`、`file_other` 这样的 CLDR 后缀，调用时必须传名为 `count` 的参数，缺少时不会回到基础键。

**来源：** i18next 文档

## 日期和货币

### 日期格式只留一份，集中格式化 【必须】

项目只有一个日期格式化模块，内部用命名预设，业务代码只传预设名。不在组件里写 `toLocaleDateString()` 或格式字符串。`Intl.DateTimeFormat` 实例按语言、时区和预设缓存后复用。

**原因：** 多份格式迟早不一致。反复调用 `toLocaleDateString` 每次都要查询本地化数据，开销更大。

**示例：**

反例：

```tsx
<td>{new Date(order.createdAt).toLocaleDateString('zh-CN')}</td>
```

正例：

```tsx
<td>{formatDate(order.createdAt, 'dateTime')}</td>
```

**来源：** 团队、MDN

### 数字和货币用 `Intl.NumberFormat` 【推荐】

不手写千分位，不拼接货币符号。货币写明 ISO 4217 代码，代码来自数据，不靠语言推断。接口金额是最小货币单位时，先按币种的小数位数换算，各币种小数位数不同。这部分也放在格式化模块中。

**示例：**

```ts
new Intl.NumberFormat(locale, { style: 'currency', currency }).format(amount);
```

**来源：** MDN

### 其他本地化输出也用 `Intl` 【推荐】

相对时间用 `Intl.RelativeTimeFormat`，列表用 `Intl.ListFormat`，用户可见文字的排序用 `Intl.Collator`。测试和逻辑不和写死的格式化字符串比较，需要其中一部分时用 `formatToParts()`。

**原因：** 输出随实现、语言和版本变化。

**来源：** MDN

## 时区

### 区分时刻和本地日期 【必须】

下单时间这类时刻用 UTC 传输，字符串带 `Z`，解析时也接受合法偏移，显示时转换。生日、节假日这类本地日期按 `YYYY-MM-DD` 处理，不转成 `Date` 后再按本地时区显示。不解析 ISO 8601 以外的格式，它们的行为由实现决定。

**原因：** `new Date('2026-03-01')` 按 UTC 解析，在 UTC 以西的时区显示为前一天。不带偏移的日期时间又按本地时间解析。

**来源：** W3C 时区说明、MDN

### 服务端渲染时明确时区 【必须】

服务端渲染的时间格式化要传 `timeZone`，取用户设置或业务所在地，不依赖运行环境的默认时区。纯客户端渲染可以用浏览器时区，业务要求固定时区时同样传入。

**原因：** 默认值是运行环境的时区，服务端和浏览器可能不同，渲染结果会不一致。

**来源：** MDN

### 未来事件保存 IANA 时区 【推荐】

预约、重复事件保存本地时间和 `Asia/Shanghai` 这类时区 ID，不只存偏移。不假设一天固定 24 小时。

**原因：** 夏令时和时区规则可能变化，只存偏移会算错未来的本地时间。

**来源：** W3C 时区说明

## RTL

### 方向写在 HTML 上 【推荐】

RTL 页面在 `<html>` 写 `dir="rtl"`，同时写 `lang`。不用 CSS 的 `direction` 设置页面方向，语言也不决定方向。

**原因：** 方向属于内容含义，样式表不可用时也要保留。

**来源：** W3C 文字方向说明

### 用逻辑属性代替左右 【推荐】

用 `margin-inline-start`、`padding-inline`、`inset-inline-end`、`text-align: start` 代替 `margin-left` 这类属性。Tailwind 用 `ms-*`、`me-*`。需要支持 RTL 的项目此条为必须。

**原因：** 同一份样式能随 `dir` 翻转，不需要单独的 RTL 样式表。

**来源：** MDN、web.dev Learn CSS、W3C 文字方向说明、Tailwind CSS 文档

### 隔离方向未知的文字 【推荐】

用户名这类插入句中的内容用 `<bdi>` 包裹。用户输入的内容和输入框用 `dir="auto"`。返回箭头这类方向性图标在 RTL 下翻转，Logo 不翻转。

**原因：** 混排时插入的文字会打乱周围的顺序。`dir="auto"` 只看第一个强方向字符，并不总是准确。

**来源：** W3C 文字方向说明

## 文案长度

### 布局为翻译增长留空间 【推荐】

文字容器用弹性布局，不写死宽高，按钮和标签允许换行或扩展。短文案增长最多：英文译为欧洲语言时，10 个字符以内可达 200% 到 300%，70 个字符以上约 130%。中文原文紧凑，译成其他语言通常更长。

**原因：** 按中文宽度做的按钮，译文容易溢出或被截断。

**来源：** W3C 文本长度说明

### 考虑不同文字的排版 【推荐】

德语等语言的长复合词不易换行，可用 CSS `hyphens`。泰语、阿拉伯语等需要更大的行高，行高不要写死。用伪翻译或最长的目标语言检查截断和对齐。

**来源：** W3C 文本长度说明、web.dev Learn Design
