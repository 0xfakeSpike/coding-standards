# 容器

## Dockerfile

### 运行镜像只保留运行所需文件 【推荐】

有编译或打包步骤时使用多阶段构建，编译工具留在构建阶段。

**来源：** Docker 构建最佳实践

### 选择小型可信的基础镜像 【必须】

**适用：** 线上服务

固定基础镜像版本，需要严格可复现时用 digest 锁定，并用自动化工具更新。

**来源：** Docker 构建最佳实践

### 用 `.dockerignore` 排除无关文件 【必须】

避免把本地依赖、构建产物和密钥带入构建上下文。

**来源：** Docker 构建最佳实践

### 合理排序以利用缓存 【推荐】

变化少的步骤放前面，比如先复制依赖清单并安装依赖，再复制源码。

### 包安装写在同一层 【必须】

`apt-get update` 和 `apt-get install` 写在同一个 `RUN` 中，否则可能用到过期的包索引缓存。

**来源：** Docker 构建最佳实践

### 以非 root 用户运行 【必须】

**适用：** 线上服务

减小容器被攻破后的影响范围。

### 镜像不含密钥 【必须】

密钥在运行时注入。构建时需要时，使用构建密钥机制，不写入镜像层。

### 定期重建镜像 【推荐】

重建时刷新基础镜像，获取安全更新。

**来源：** Docker 构建最佳实践

## 镜像标签

### 不用 `latest` 部署 【必须】

**适用：** 线上服务

部署时使用不可变标签，比如提交 SHA 或版本号，这样才能确定线上运行的内容。

## 进程

### 进程无状态，快速启动，优雅关闭 【必须】

**适用：** 线上服务

收到终止信号后停止接收新请求，完成进行中的工作再退出。数据库这类有状态组件不要求无状态。

**来源：** Twelve-Factor App

### 日志写入标准输出 【必须】

**适用：** 线上服务

把日志当作事件流，由平台收集，不在容器内管理日志文件。

**来源：** Twelve-Factor App

## Kubernetes 探针

**适用：** 线上服务（本节全部规则）

### 按用途选择探针 【必须】

| 探针 | 失败后 | 用途 |
|---|---|---|
| startup | 超过阈值后重启容器，成功前其他探针不执行 | 保护启动慢的容器 |
| liveness | 超过阈值后重启容器 | 死锁等无法自行恢复的状态 |
| readiness | 从服务端点摘除，不重启 | 暂时不能接收流量 |

**来源：** Kubernetes 探针

### liveness 不检查外部依赖 【必须】

数据库短暂故障时重启应用没有帮助，还可能造成连锁重启。

### readiness 不包含共享依赖 【推荐】

readiness 只包含实例独占且必需的依赖。共享依赖短暂故障时，所有实例会被同时摘除流量。

## Kubernetes 资源

### 设置 requests 和内存 limit 【必须】

**适用：** 线上服务

request 决定调度，limit 是运行上限。内存超过 limit 时容器可能被 OOM 杀死。CPU limit 按负载决定是否设置，达到 limit 时容器会被节流。

**来源：** Kubernetes 资源管理

### 注意内存单位 【必须】

使用 Kubernetes 时，`M` 和 `m` 含义不同，内存不要写成 `400m`。

**来源：** Kubernetes 资源管理

### 配置与镜像分离 【必须】

**适用：** 线上服务

配置放环境变量或 ConfigMap，敏感配置放 Secret 或外部密钥服务。

**来源：** Twelve-Factor App
