# RAG 工程规范

本文规定检索增强生成的索引、切分和评估。搜索引擎的使用见 [文档与搜索存储](../data/document-and-search.md)，Agent 和提示注入防护见 [Agent 工程规范](agents.md)。

## 选型

### 先判断是否需要 RAG 【推荐】

知识库小到能完整放入上下文，且成本和延迟可接受时，直接放入，不建检索链路。

**来源：** Anthropic Contextual Retrieval

## 索引

### 索引是可重建的派生数据 【推荐】

源文档是唯一事实来源，索引只保存可由源文档重新生成的内容。索引记录生成它的切分配置和嵌入模型，查询向量和文档向量必须来自同一模型。

**原因：** 不同模型的向量不可比较，混用时不会报错，只有结果悄悄变差。

### 同时使用词法和向量检索 【推荐】

向量检索擅长语义相近的内容，但可能漏掉精确匹配。词法检索擅长标识符和专业术语。合并两路结果后再重排，把少量最相关的片段交给模型。召回数量和最终片段数通过评估确定。

**原因：** 片段太少容易漏信息，太多会干扰模型并增加成本。

**来源：** Anthropic Contextual Retrieval

### 权限在检索时过滤 【必须】

数据有租户或访问分级时，每个片段都带这些信息，多租户数据按权限分区。权限条件由调用方根据当前用户传入，并在搜索内部生效，不在结果返回后再由模型或提示词筛选。

**原因：** 共用向量库时，一个租户的内容可能出现在另一个租户的查询结果中。

**示例：**

```json
{"query": "退款时效", "filter": {"tenant_id": "t_9", "access_level": ["public", "staff"]}, "top_k": 50}
```

**来源：** OWASP LLM Top 10

### 入库前校验内容 【推荐】

只接收可信来源的文档，入库前做校验。提取文本时要能暴露隐藏内容，例如白色文字和不可见图层。

**原因：** 文档中隐藏的指令会随检索进入上下文，影响模型输出。

**来源：** OWASP LLM Top 10

### 索引与源文档同步 【必须】

**适用：** 线上服务

用内容哈希判断文档是否变化，只处理变化的部分。文档更新时替换它的全部旧片段，文档删除时同步删除所有片段。

**原因：** 残留片段会继续被引用，已删除的敏感内容也可能泄露。

## 切分

### 按文档结构切分 【推荐】

优先按标题、段落、表格、代码块切分，不在句子或表格中间截断。片段大小和重叠放在配置中，用评估集比较后确定，不照搬经验值。

**来源：** Anthropic Contextual Retrieval

### 片段保留上下文 【推荐】

脱离原文后含义不清的片段，在索引时补充文档标题、章节路径或简短说明。

**示例：** “该季度收入增长 3%”单独看不出主体，索引时补上公司和季度。

**来源：** Anthropic Contextual Retrieval

### 片段保留来源信息 【推荐】

每个片段保存文档标识和文档版本，需要定位原文时再保存章节和位置。

**原因：** 缺少来源信息时，无法在文档更新后识别过期片段。

**示例：**

```json
{"chunk_id": "c_18", "document_id": "d_3", "document_version": "a91f"}
```

## 引用

### 校验模型给出的引用 【必须】

模型输出引用时，确认它对应本次实际提供的片段，不存在的不展示。链接由系统根据片段来源生成，模型输出的 URL 不直接展示。

**原因：** 模型可能编造链接，注入内容也可能借助链接把用户引向恶意地址。

## 评估

### 分开评估检索和生成 【推荐】

只看最终回答，无法判断问题出在检索还是生成。至少覆盖下表四项，指标由 Ragas 这类工具或自建脚本计算。

| 环节 | 指标 | 含义 |
|---|---|---|
| 检索 | 上下文召回率 | 参考答案中的论断有多少被检索结果支持 |
| 检索 | 上下文精确率 | 相关片段是否排在前面 |
| 生成 | 忠实度 | 回答中的论断有多少被检索内容支持 |
| 生成 | 回答相关性 | 回答是否切题，不评估事实是否正确 |

只调检索时，也可以用 top-K 召回率直接比较，它需要标注相关片段。

**工具：** Ragas

**来源：** Ragas 文档、Anthropic Contextual Retrieval

### 维护固定评估集 【推荐】

评估集由真实问题、参考答案和相关文档组成，要包含无答案的问题和容易混淆的问题。起步时几十条就够用，线上发现的错误案例持续补入。

**原因：** 早期改动的效果差异很大，少量样本就能看出来。没有固定集合时，无法比较两次改动。

**来源：** Anthropic 多智能体系统、Ragas 文档

### 改动必须附带评估结果 【推荐】

调整切分、嵌入模型、召回数量、重排或提示词时，在同一评估集上对比改动前后的指标。测试组织方式见 [后端测试](../testing.md)。

**来源：** Anthropic Contextual Retrieval

### 模型评分要经过人工校验 【推荐】

基于模型的指标会调用模型，分数有波动。评分用的模型和提示词要固定，定期抽样人工复核，人工还要覆盖自动评估发现不了的边角案例。

**来源：** Ragas 文档、Anthropic 多智能体系统

### 线上记录检索过程 【推荐】

每次检索生成 `gen_ai.retrieval` span，记录 `gen_ai.retrieval.top_k`、耗时和命中数。查询文本和文档内容默认不记录，需要时显式开启。检索日志还用于发现可疑访问。

**来源：** OTel GenAI 语义约定、OWASP LLM Top 10
