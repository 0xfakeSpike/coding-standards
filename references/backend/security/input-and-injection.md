# 输入与注入

本文讲如何处理不可信数据。语言特有的危险函数见 `languages/<语言>/security.md`。文件名和上传内容见 [文件处理](file-handling.md)，请求体大小和分页上限见 [审计与防滥用](audit-and-abuse.md)。

## 校验

### 所有跨越信任边界的输入都校验 【必须】

包括请求参数、Header、Cookie、文件、回调、消息队列内容，也包括内部接口、合作方数据和从存储读回的记录。校验在服务端完成，客户端校验只用于即时反馈。

**原因：** 客户端校验可以绕过，内部链路也不能保证数据符合接收方的规则。

**来源：** OWASP 输入校验速查表、OWASP ASVS

### 先限制大小，再解析，再校验 【必须】

**适用：** 高风险

缓冲或解析之前先限制请求大小，并配置解析器的深度上限。用维护中的解析器解析，再校验解析结果。按协议解码一次，校验实际要使用的值，下游不再重复解码。

**原因：** 解析之后的 Schema 校验保护不了解析器本身。

**来源：** OWASP 输入校验速查表、OWASP ASVS

### 按字段定义白名单规则 【必须】

定义可接受的内容，其余全部拒绝。不靠黑名单识别恶意字符串。

| 输入 | 规则 |
|---|---|
| 枚举 | 严格属于允许集合 |
| 数字和日期 | 类型、格式、最小值、最大值 |
| 字符串 | 长度上限，字符或结构要求 |
| 对象 | 必填字段、允许字段、null 的处理 |
| 数组 | 元素数量上下限，逐项校验，包括嵌套对象 |

**来源：** OWASP 输入校验速查表

### Schema 显式拒绝未知字段 【必须】

JSON Schema 中列出属性不等于要求或限制它。必须同时声明 `required` 和 `additionalProperties`。校验库默认忽略或剥离未知字段时，开启严格模式或等价配置。

```json
{
  "type": "object",
  "required": ["sku", "quantity"],
  "additionalProperties": false,
  "properties": {
    "sku": { "type": "string", "maxLength": 32 },
    "quantity": { "type": "integer", "minimum": 1, "maximum": 99 }
  }
}
```

**来源：** OWASP 输入校验速查表

### 校验业务语义 【必须】

语法合法之外还要校验语义，比如结束日期晚于开始日期，字段组合互相匹配。多步流程按预期顺序执行，不能跳步。

**来源：** OWASP 输入校验速查表、OWASP ASVS

### 校验失败就拒绝 【必须】

返回明确错误，不带着部分校验的数据继续处理。不“清洗”输入后接着用，删除可疑字符会改变含义，也起不到参数化和输出编码的作用。

**例外：** 分页大小超过上限时按 [rest.md](../api/rest.md) 处理，其余数值超出范围一律拒绝。

**来源：** OWASP 输入校验速查表

### 正则匹配完整值并防 ReDoS 【必须】

**适用：** 高风险

要求匹配整个值，匹配前先限制长度，避免过度回溯的模式，优先用非回溯引擎或匹配超时。

**来源：** OWASP 输入校验速查表、OWASP ASVS

### 关键业务值由服务端计算 【必须】

价格、折扣、金额、库存这类数据由服务端根据可信数据计算，不信任客户端传值。

**原因：** 客户端传值可以被任意修改。

## 注入的通用原则

### 数据和指令分离 【必须】

不用字符串拼接把外部数据放进任何解释器能执行的语句。优先用该解释器的参数化接口，没有时再用针对该上下文的编码。输出编码放在交给解释器之前的最后一步。

| 解释器 | 做法 |
|---|---|
| SQL、HQL、NoSQL、图查询 | 参数化查询 |
| 系统命令 | 库函数，或参数数组 |
| LDAP | 专用编码函数 |
| XPath | 参数化或预编译查询 |
| 模板和表达式语言 | 模板固定，数据只作为变量传入，不交给 `eval` 求值 |
| 邮件 | 校验收件人和头字段，防止注入额外头 |
| HTML 富文本 | 用维护中的净化库 |

**来源：** OWASP ASVS

## SQL 注入

### 使用参数化查询 【必须】

来自请求、其他服务或已存储的数据一律绑定参数。ORM 和存储过程里的原生 SQL 同样要参数化。手工转义依赖方言和配置，不作为替代方案。

反例：

```text
"SELECT id FROM users WHERE email = '" + input + "'"
```

正例：

```sql
SELECT id FROM users WHERE email = ?;
```

**工具：** Semgrep

**来源：** OWASP SQL 注入防护速查表、OWASP ASVS

### 动态结构用固定映射 【必须】

占位符只能代表值，不能代表表名、列名和 `ASC`。排序字段这类结构，把外部值映射到代码中固定的选项，比如 `created` 映射为 `created_at`。

**来源：** OWASP SQL 注入防护速查表

### 数据库账号最小权限 【推荐】

应用账号不用管理员权限，只授予所需的表和操作。这只能限制损失，不能防止注入。

**来源：** OWASP SQL 注入防护速查表

## 命令注入

### 优先不调用系统命令 【必须】

能用库函数完成的，不启动外部进程。必须调用时：命令来自固定白名单，用参数数组而不是拼接成 Shell 字符串，参数逐个白名单校验，支持时用 `--` 结束选项解析。

**示例：** `["convert", "--", "/data/tmp/9f2c.png", "/data/tmp/out.png"]`

**原因：** 不经过 Shell 时，以 `-` 开头的值仍可能注入选项。

**来源：** OWASP 命令注入防护速查表、OWASP ASVS

## 模板注入

### 不用外部输入构造模板 【必须】

模板内容来自代码或受控配置，外部数据只作为变量渲染。需要用户自定义模板时，用逻辑受限的模板语言或严格沙箱。

**示例：** 不写 `render("你好，" + input)`，写 `render("你好，{{name}}", { name: input })`。

**来源：** OWASP ASVS

## 批量赋值

### 不把请求体直接绑定到实体 【必须】

用 DTO 或显式字段列表限定可写字段。否则用户可以传入 `role`、`isAdmin`、`balance` 这类字段。

**来源：** OWASP 批量赋值速查表、OWASP API Security Top 10

## 反序列化与 XML

### 不用语言原生序列化处理不可信数据 【必须】

使用 JSON 这类纯数据格式。必须使用时，限制允许的类型，并在反序列化之前校验签名。具体函数见语言层。

**原因：** 原生反序列化可能导致拒绝服务、越权或远程代码执行。

**来源：** OWASP 反序列化速查表、OWASP ASVS

### XML 解析器禁用外部实体 【必须】

尽量禁用 DTD，拒绝 `DOCTYPE`。确实需要 DTD 时，禁用外部实体和外部 DTD，并限制实体展开。解析器不支持某项加固设置时，不继续处理不可信 XML。

**原因：** XXE 会导致读取本地文件、SSRF 和资源耗尽。

**来源：** OWASP XXE 速查表、OWASP ASVS

## 导出内容

### CSV 导出防公式注入 【推荐】

导出到 CSV 或表格时，按 RFC 4180 转义，并用单引号转义以 `=`、`+`、`-`、`@`、制表符或空字符开头的单元格。

**原因：** 用户数据可能在表格软件中被当作公式执行。

**来源：** OWASP ASVS
