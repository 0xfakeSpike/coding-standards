# 授权

本文讲确认身份之后“能做什么”。身份从哪里来见 [认证](authentication.md)，授权失败的记录见 [审计与防滥用](audit-and-abuse.md)。

## 基本要求

### 默认拒绝 【必须】

每个接口默认需要鉴权，公开接口显式声明。没有匹配到任何规则时拒绝。不依赖框架的默认行为，用显式配置。

**原因：** 忘记配置时结果是拒绝访问，而不是对外开放。

**工具：** 在集成测试中枚举全部路由，断言未声明公开的路由在未登录时返回 401。

**来源：** OWASP 授权速查表、OWASP API Security Top 10

### 在可信的服务端逐请求校验 【必须】

每个请求都校验权限，用全局的中间件或拦截器统一接入，不靠每个处理函数自己记得调用。客户端隐藏按钮只改善体验，不算访问控制。静态资源和导出文件同样要校验。

**来源：** OWASP 授权速查表、OWASP ASVS

### 用户身份取自认证上下文 【必须】

操作者身份、租户和角色都从已验证的令牌或会话读取，不信任请求参数或请求体中的 `userId`、`role`。

**来源：** OWASP 多租户安全速查表

### 授权失败时安全退出 【必须】

校验过程抛错时按拒绝处理，集中处理失败逻辑，错误信息不暴露内部细节。

**原因：** 失败路径上的放行是常见的授权绕过原因。

**来源：** OWASP 授权速查表、OWASP ASVS

### 权限变更尽快生效 【必须】

**适用：** 线上服务

角色、成员关系变更后立即生效。权限写在自包含令牌里而无法立即生效时，缩短令牌有效期，并对高风险操作重新查询当前权限。

**来源：** OWASP ASVS

### 最小权限 【必须】

**适用：** 线上服务

用户、数据库账号、云角色和服务账号只授予必要权限。

**来源：** OWASP 授权速查表

## 模型选择

### 按授权问题的形状选模型 【推荐】

| 模型 | 判断依据 | 适用场景 |
|---|---|---|
| RBAC | 用户拥有的角色 | 功能入口、后台菜单等粗粒度权限 |
| ABAC | 主体、资源、环境的属性 | 依赖数据状态、部门、时间的规则 |
| ReBAC | 主体与资源的关系 | 所有者、协作者、分享 |

只用角色难以表达对象级规则，角色数量也容易膨胀。需要对象级或跨组织规则时，优先用 ABAC 或 ReBAC。

**来源：** OWASP 授权速查表

### 权限判断集中定义 【推荐】

业务代码调用统一的授权模块询问“能否执行某动作”，比如 `authorize(user, "order:refund", order)`，不散落 `role == "admin"` 这样的判断。

**来源：** OWASP API Security Top 10

## 对象级和字段级权限

### 校验对象级权限 【必须】

只校验登录不够，还要校验当前用户能否操作这条数据。每个用客户端传入的 ID 访问数据的函数都要校验。这是最常见的越权漏洞（IDOR 或 BOLA）。

反例：

```sql
SELECT id, amount FROM orders WHERE id = ?;
```

正例：

```sql
SELECT id, amount FROM orders WHERE id = ? AND user_id = ?;
```

查不到时返回 404，不区分“不存在”和“无权访问”。

**原因：** 任何登录用户都能通过改 ID 读取他人数据。

**工具：** 为每个对象接口写一条用另一用户身份访问的负向测试。

**来源：** OWASP API Security Top 10、OWASP 授权速查表、OWASP ASVS

### 随机 ID 不能替代权限校验 【必须】

不可预测的 ID 可以增加枚举难度，但 ID 会出现在日志、链接和分享中，不是访问控制。

**来源：** OWASP 授权速查表、OWASP 多租户安全速查表

### 校验功能级权限 【必须】

管理接口单独做权限校验，不靠路径隐蔽。普通控制器中的管理动作同样要校验。

**来源：** OWASP API Security Top 10

### 校验字段级权限 【必须】

读写都要按字段校验。响应只返回当前调用者有权看到的字段，写入只接受有权修改的字段，写入规则见 [输入与注入](input-and-injection.md)。

**来源：** OWASP API Security Top 10、OWASP ASVS

## 多租户隔离

### 租户上下文来自服务端验证 【必须】

请求开始时确定租户，绑定到已验证身份和当前成员关系。请求头或参数中的租户 ID 只是选择器，必须校验调用者属于该租户。

**来源：** OWASP 多租户安全速查表

### 在数据访问层强制租户条件 【必须】

租户条件由所有请求都会经过的一层统一施加，不靠业务代码逐条查询添加。共享表可用行级安全作为第二道防线，此时请求路径的数据库账号不能绕过策略。租户上下文绑定到事务，归还连接前清除。缺少租户上下文时直接失败，不退回无租户条件的查询。

**原因：** 连接池复用时，会话级的租户设置可能串到下一个请求。

**工具：** 对每张租户表写跨租户访问的负向测试。

**来源：** OWASP 多租户安全速查表、OWASP ASVS

### 缓存、文件和异步任务同样隔离 【必须】

| 位置 | 要求 |
|---|---|
| 缓存 | 随租户变化的值，键中包含租户。读缓存前先授权 |
| 文件存储 | 路径或存储桶按租户隔离，访问时校验归属 |
| 队列和任务 | 租户上下文来自已认证的生产者，消费者重新建立上下文并授权 |
| 幂等键和去重 | 结果随租户变化时，按租户划分 |
| 限流和配额 | 按租户计量，防止一个租户耗尽共享资源 |

缓存键设计见 [缓存与 Redis](../data/cache-and-redis.md)，消息设计见 [消息](../async/messaging.md)。

**来源：** OWASP 多租户安全速查表

### 跨租户操作显式授权 【必须】

运维和数据修复这类跨租户路径，走单独的身份和授权，并记录审计日志。普通请求路径不存在跨租户查询。

**来源：** OWASP 多租户安全速查表

## 服务间鉴权

### 内部调用也要认证和授权 【推荐】

处于内网不是信任依据。服务之间相互认证，被调用方校验调用方身份和令牌受众。优先用 mTLS 或短期的工作负载身份令牌，不用长期共享的静态密钥。

**来源：** OWASP ASVS、OWASP 多租户安全速查表

### 按发起者的权限访问 【必须】

**适用：** 线上服务

服务代用户操作时，传递用户身份并按用户权限判断，不用服务账号的高权限直接读取。

**原因：** 否则中间服务会成为被借用的高权限入口。

**来源：** OWASP ASVS

### 用户不能伪造网关注入的头 【必须】

网关写入的身份头，如 `X-User-Id`，必须先清除外部传入的同名头。后端只接受来自网关的流量，否则不信任这些头。

**来源：** OWASP ASVS

## 验证

### 授权逻辑必须有自动化测试 【必须】

**适用：** 线上服务

覆盖默认拒绝、越权访问、跨租户访问和失败路径。测试不通过不能部署。

**来源：** OWASP 授权速查表、OWASP API Security Top 10
