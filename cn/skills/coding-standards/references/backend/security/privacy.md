# 隐私与个人信息

本文只列工程实现要点，不构成法律意见。条款号对应《中华人民共和国个人信息保护法》（下称 PIPL）和欧盟 GDPR。

**适用：** 高风险（本文全部规则）

## 数据分级

### 建立个人数据清单 【推荐】

记录系统处理哪些个人数据、存放位置、接收方和保存期限，随表结构和接口变更一起更新。

**原因：** 不知道数据在哪里，就无法响应删除和查阅，也无法评估泄露影响。

**来源：** GDPR、个人信息保护法、OWASP ASVS

### 按级别定义保护要求 【推荐】

每个字段归入一个级别，每个级别写明加密、访问、日志和保存要求。下表是起点，按业务调整。

| 级别 | 示例 | 要求 |
|---|---|---|
| 公开 | 公开的商品信息 | 无特殊要求 |
| 内部 | 工单、运营数据 | 登录访问 |
| 个人信息 | 姓名、手机号、邮箱、地址 | 最小权限、脱敏展示、不入日志明文 |
| 敏感个人信息 | 证件号、生物识别、医疗健康、金融账户、行踪轨迹、未满十四周岁未成年人信息 | 字段加密、访问审计、单独同意 |

**来源：** OWASP ASVS、个人信息保护法

### 按法律定义识别敏感数据 【推荐】

PIPL 第二十八条列出的类别包括生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹和不满十四周岁未成年人的信息。GDPR 第 9 条第 1 款的特殊类别还包括种族、政治观点、工会会员身份、基因数据和性取向等。两者范围不同，面向两地的系统取并集。

**来源：** 个人信息保护法、GDPR

## 最小化

### 收集范围限于处理目的 【必须】

每个字段都要能说明用途，用不到就不收集。默认配置只处理目的所必需的数据。PIPL 第六条要求限于实现目的的最小范围，GDPR 第 5 条第 1 款 (c) 项和第 25 条有同类要求。

**示例：** 只需验证成年时，存“是否成年”，不存出生日期。

**来源：** 个人信息保护法、GDPR

### 接口只返回必要字段 【必须】

列表和详情分别定义响应字段。确需完整值时才返回完整值，其他情况脱敏。

反例：

```json
{ "name": "张三", "idNumber": "<完整证件号>", "phone": "<完整手机号>" }
```

正例：

```json
{ "name": "张*", "phone": "138****1234" }
```

**来源：** OWASP ASVS

### 控制个人数据的扩散 【必须】

个人数据不放在 URL 和查询参数里，不写入浏览器本地存储，含个人数据的响应用 `Cache-Control: no-store`。姓名、手机号、邮箱这类直接标识符不发送给埋点和第三方统计。假名 ID 只发给已列入数据清单的委托处理方，且只传必要字段。日志规则见 [审计与防滥用](audit-and-abuse.md)，测试环境不用未处理的生产数据。

**来源：** OWASP ASVS

### 区分去标识化和匿名化 【推荐】

去标识化后借助额外信息仍能识别个人，数据仍属于个人信息。匿名化后无法识别且不能复原，才不再是个人信息（PIPL 第四条、第七十三条）。对手机号做无密钥哈希不是匿名化，因为可以被枚举还原。

**来源：** 个人信息保护法

## 同意与告知

### 同意按用途记录 【必须】

记录谁、何时、对哪个版本的规则、同意了什么用途，需要时能证明（GDPR 第 7 条第 1 款）。处理目的、方式或信息种类变更时重新取得同意（PIPL 第十四条）。

**来源：** GDPR、个人信息保护法

### 撤回同意和作出同意一样方便 【必须】

提供便捷的撤回入口，撤回后下游停止相应处理（PIPL 第十五条，GDPR 第 7 条第 3 款）。不以不同意为由拒绝服务，除非该处理是提供服务所必需的（PIPL 第十六条）。

**来源：** 个人信息保护法、GDPR

### 需要单独同意的场景单独做开关 【必须】

敏感个人信息（第二十九条）、向其他处理者提供（第二十三条）、公开（第二十五条）、向境外提供（第三十九条）需要单独同意，不能和其他条款打包勾选。处理不满十四周岁未成年人的信息，要取得监护人同意（第三十一条）。

**来源：** 个人信息保护法

## 留存和删除

### 每类数据都有保存期限 【必须】

保存期限为实现目的所必要的最短时间，法律另有规定的除外（PIPL 第十九条，GDPR 第 5 条第 1 款 (e) 项）。期限写入配置，由定时任务执行，不依赖人工。

| 数据 | 期限来源 | 到期动作 |
|---|---|---|
| 账号资料 | 注销后的约定期限 | 删除 |
| 交易记录 | 法定保存期限 | 到期删除，期间限制使用 |
| 访问日志 | 安全和法定要求 | 自动过期 |

**工具：** 对象存储生命周期规则、数据库分区过期。

**来源：** 个人信息保护法、GDPR、OWASP ASVS

### 删除覆盖所有副本 【必须】

删除要覆盖主库、缓存、搜索索引、数据仓库、文件存储、死信和失败任务的输入、第三方接收方。备份按保留周期自然过期，恢复备份后要重新执行已发生的删除。审计记录只存内部标识，保存期内按“已限制处理”对待，到期删除。

**原因：** 只删主库时，数据仍能从索引和报表中查到。

### 触发删除的条件要落到流程 【必须】

PIPL 第四十七条要求在目的已实现、停止服务、保存期限届满、撤回同意、违法处理时主动删除。法定保存期未满或技术上难以删除时，停止存储和安全保护之外的处理。GDPR 第 17 条第 3 款也列有例外。系统要支持“已限制处理”这一状态。

**来源：** 个人信息保护法、GDPR

## 个人权利

### 提供查阅、更正、删除、导出的能力 【必须】

这些能力要有接口或后台流程，不靠手工查库（PIPL 第四十五条至第四十七条、第五十条，GDPR 第 12 条、第 15 条、第 17 条、第 20 条）。

| 要求 | 工程含义 |
|---|---|
| 导出 | 结构化、常用、机器可读的格式，比如 JSON 或 CSV |
| 身份核验 | 执行前确认请求者是本人，防止成为泄露入口 |
| 时限 | GDPR 一般为一个月内，PIPL 要求及时处理，工单记录时间 |
| 拒绝 | 说明理由并留存记录 |
| 他人数据 | 导出时不包含其他人的信息 |

**来源：** 个人信息保护法、GDPR

## 事件

### 泄露事件能快速定位和通知 【推荐】

日志和数据清单要能回答泄露了哪些数据、影响哪些人。PIPL 第五十七条要求立即补救并通知，GDPR 第 33 条要求在可行时于知悉后 72 小时内通知监管机构。

**来源：** 个人信息保护法、GDPR
