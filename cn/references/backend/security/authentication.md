# 认证

本文讲如何确认“你是谁”。确认身份后“能做什么”见 [授权](authorization.md)，登录限流和撞库防护见 [审计与防滥用](audit-and-abuse.md)，算法和密钥见 [加密与密钥](crypto-and-secrets.md)。语言相关的 API 见 `languages/<语言>/security.md`。

## 密码

### 用专用密码哈希算法存储 【必须】

优先用 Argon2id，不可用时用 scrypt，两者都不可用时才用 bcrypt。需要 FIPS 合规时用 PBKDF2。不用 MD5、SHA-1 或其他快速哈希，也不做可逆加密。

| 算法 | 最低参数 |
|---|---|
| Argon2id | m=19456（19 MiB）、t=2、p=1 |
| scrypt | N=2^17、r=8、p=1 |
| bcrypt | 工作因子不低于 10，输入不超过 72 字节 |
| PBKDF2-HMAC-SHA256 | 600000 次迭代 |

**原因：** 快速哈希在数据库泄露后可被大规模破解。

**来源：** OWASP 密码存储速查表、NIST SP 800-63B

### 使用 bcrypt 时处理长密码 【必须】

新系统不选 bcrypt。必须使用时，长密码要有明确的处理方案，比如带密钥的预哈希，并写明编码，不静默截断。

**原因：** 64 个中文字符在 UTF-8 下约 192 字节，超过 bcrypt 的 72 字节上限。

### 密码策略看长度和黑名单，不看字符组合 【推荐】

只用密码登录时最小长度为 15，密码只作为 MFA 的一个因子时最小长度为 8。允许至少 64 个字符，允许粘贴和密码管理器。不要求混合字符类型，不强制定期改密。设置密码时，将完整密码与常用、已泄露密码的黑名单比对。有证据表明密码已泄露时强制修改。

**来源：** NIST SP 800-63B、OWASP ASVS

### 密码流程不留捷径 【必须】

**适用：** 线上服务

按收到的原样校验密码，不截断、不改大小写。改密时要求当前密码。不提供密码提示和安全问题。删除或禁用 `admin`、`root` 这类默认账号。系统生成的初始密码随机、短期有效，不能作为长期密码。

**来源：** OWASP ASVS

### 认证失败不泄露账号是否存在 【必须】

**适用：** 高风险

用户不存在、密码错误、账号锁定时，返回相同的提示和状态码，响应时间保持接近。用户不存在时也要执行一次哈希计算，不能提前返回。找回密码同样要满足。注册时能否做到取决于是否有邮箱验证流程，有时同样要满足。

**原因：** 提示、状态码或耗时的差异都能被用来枚举账号。

**来源：** OWASP 认证速查表、OWASP ASVS

## 多因素认证

### 高权限账号必须启用 MFA 【必须】

**适用：** 高风险

管理员和其他高权限账号强制启用，普通用户至少能自行开启。所有登录入口执行相同的认证强度，包括单独提供的 API 登录。

**来源：** OWASP 多因素认证速查表

### 优先选防钓鱼的因子 【推荐】

优先级依次为 Passkey 或 WebAuthn、TOTP、短信。短信存在 SIM 卡劫持和拦截风险，属于受限方式，高价值业务不使用。邮件不作为带外认证方式。

**来源：** NIST SP 800-63B、OWASP 多因素认证速查表

### 一次性验证码短期、单次、限次 【必须】

用 CSPRNG 生成，校验成功后立即作废。带外验证码有效期不超过 10 分钟，TOTP 不超过 30 秒。验证码绑定发起它的那次请求，校验次数有上限。推送式 MFA 要限频。

**来源：** OWASP ASVS、OWASP 多因素认证速查表

### 修改认证因子要重新认证 【必须】

**适用：** 高风险

修改邮箱、手机号、MFA 设置或恢复方式之前，用已绑定的因子完整认证一次，不能只依赖当前会话。完成后通过带外渠道通知用户。恢复码只能使用一次。

**原因：** 被劫持的会话如果能直接替换因子，账号主人会被锁在外面。

**来源：** OWASP 多因素认证速查表、OWASP ASVS

## 会话

### 会话 ID 由服务端用 CSPRNG 生成 【必须】

优先用框架的会话实现。自行生成时至少 128 位熵，ID 不含用户信息。威胁模型包含会话库只读泄露时，库中只存令牌的哈希。

**来源：** OWASP 会话管理速查表、OWASP ASVS

### 认证状态变化时轮换会话 【必须】

登录、重新认证和权限提升时生成新会话并作废旧会话。改密或重置密码后使其他会话失效。账号停用或删除时终止全部会话。

**原因：** 不轮换会导致会话固定攻击，旧会话也可能仍被攻击者持有。

**来源：** OWASP 会话管理速查表、OWASP ASVS

### Cookie 设置完整的安全属性 【必须】

会话 Cookie 必须带 `HttpOnly`、`Secure` 和合适的 `SameSite`，优先用 `__Host-` 前缀。基于 Cookie 的认证还要防护 CSRF，见 [Web 风险](web-risks.md)。

```http
Set-Cookie: __Host-sid=<value>; Path=/; Secure; HttpOnly; SameSite=Lax
```

**来源：** OWASP 会话管理速查表、OWASP ASVS

### 超时和注销在服务端执行 【必须】

同时设置空闲超时和绝对超时，由服务端判断。注销时销毁服务端会话，不能只删 Cookie。具体时长按业务风险设定。按 NIST AAL2 要求的系统，空闲超时不超过 1 小时，绝对超时不超过 24 小时。按 AAL3 要求的系统，分别不超过 15 分钟和 12 小时。

**来源：** NIST SP 800-63B、OWASP 会话管理速查表、OWASP ASVS

## JWT

### 先判断是否需要 JWT 【推荐】

用户会话优先用服务端会话，把 JWT 当会话时仍要自建吊销机制。确实使用时，Access Token 短期有效，配合可撤销并轮换的 Refresh Token。需要立即失效时，用 `iss` 加 `jti` 建立拒绝列表。

**来源：** OWASP JWT 速查表

### 服务端固定算法和密钥来源 【必须】

验证方配置算法白名单，不接受 `alg: none`，一个密钥只用于一种算法。不信任令牌头中的 `jku`、`x5u`、`jwk`，密钥只取自预先配置的来源。`kid` 是外部输入，使用前先校验。HMAC 密钥随机生成，长度不短于哈希输出。

**原因：** 算法混淆和令牌自带密钥都能让伪造的令牌通过验证。

**来源：** RFC 8725、OWASP JWT 速查表、OWASP ASVS

### 校验签名、声明和令牌用途 【必须】

先验签，再读取内容。校验 `exp`、`nbf`、`iss`、`aud`，确认密钥属于该 `iss`。同一签发方的多种令牌，校验规则必须互斥，新类型用 `typ` 标注，例如 `at+jwt`。

**原因：** 否则重置令牌或 ID Token 可能被当作访问令牌接受。

**来源：** RFC 8725、OWASP JWT 速查表、OWASP ASVS

### 载荷不放敏感信息 【必须】

签名 JWT 的载荷只是编码，任何持有者都能读取。

**来源：** OWASP JWT 速查表

## OAuth 2.1 与 OIDC

### 只用授权码模式加 PKCE 【必须】

不用隐式模式和密码模式。PKCE 方法用 `S256`，每次事务生成新值。授权码只能使用一次，有效期不超过 10 分钟。回调地址做精确字符串比较，唯一例外是本地回环地址的端口号。不能存在开放重定向。

**原因：** 隐式模式会泄露令牌，密码模式把用户凭证暴露给客户端。

**来源：** RFC 9700、OAuth 2.1 草案、OWASP ASVS

### 令牌不放在 URL 中 【必须】

Access Token 用 `Authorization` 头传递，不放在查询参数里。

反例：

```http
GET /orders?access_token=eyJhbGciOi... HTTP/1.1
```

**来源：** OAuth 2.1 草案

### 限制令牌的受众和权限 【必须】

资源服务器逐请求校验 `aud`，不匹配时拒绝。客户端只申请需要的 scope。公共客户端的 Refresh Token 必须做发送方约束或轮换，Refresh Token 都有绝对过期时间。浏览器应用优先用 BFF，令牌只由后端持有。

**来源：** RFC 9700、OWASP ASVS

### 客户端完整校验响应和身份 【必须】

确认授权响应属于当前用户代理发起的事务。校验 ID Token 的签名、`iss`、`exp`，`aud` 等于自身的 `client_id`，`nonce` 与请求一致。对接多个授权服务器时用 `iss` 防混淆攻击。用 `iss` 加 `sub` 识别用户，不用可被重新分配的邮箱。

**来源：** RFC 9700、OWASP ASVS

## 重置流程

### 重置请求不泄露信息 【必须】

**适用：** 高风险

账号是否存在都返回同样的提示，耗时保持一致。按账号限频，防止邮箱被轰炸。提交有效令牌之前不改动账号状态。

**来源：** OWASP 忘记密码速查表

### 重置令牌随机、单次、短期 【必须】

用 CSPRNG 生成，绑定具体用户，只存哈希，使用后立即作废。重置链接用配置中的固定域名拼接，不用请求的 `Host` 头。重置页设置 `Referrer-Policy: no-referrer`。

**原因：** 依赖 `Host` 头时，攻击者能让发给受害者的链接指向自己的域名。

**来源：** OWASP 忘记密码速查表

### 重置完成后收尾 【必须】

**适用：** 线上服务

通知用户密码已变更，通知中不含密码。不自动登录。重置不能绕过已启用的 MFA。管理员只能发起重置，不能选定用户的新密码。

**来源：** OWASP 忘记密码速查表、OWASP ASVS
