# 审计与防滥用

本文讲安全审计、限流、防刷和账号风控。普通运行日志的规范见 [日志](../observability/logging.md)，告警见 [指标与告警](../observability/metrics-and-alerts.md)，依赖漏洞扫描见 [依赖管理](../../general/dependencies.md)。

## 审计日志

**适用：** 高风险（本节全部规则）

防止日志注入的规则见 [日志](../observability/logging.md)。

审计日志同样不记录敏感内容，规则见 [日志](../observability/logging.md)，需要关联会话时记录其哈希。

### 记录关键操作 【必须】

| 类别 | 事件 |
|---|---|
| 认证 | 登录成功和失败、登出、MFA 变更、密码修改和重置 |
| 授权 | 授权失败、权限和角色变更、管理员操作 |
| 数据 | 敏感数据访问、导出、批量删除 |
| 资金 | 支付、退款、提现 |
| 系统 | 配置修改、密钥轮换、破窗账号使用 |
| 防护 | 校验失败、反序列化失败、业务流程被绕过、超出限制 |

**原因：** 没有这些记录，发生事故时无法判断影响范围。

**来源：** OWASP 日志速查表、OWASP ASVS

### 每条记录说明谁、何时、何处、做了什么 【必须】

至少包含操作者、时间、来源、动作、对象和结果。时间用 UTC，带 `Z`，各节点时钟同步。多租户系统记录已验证的租户。

```json
{
  "time": "2026-11-05T08:30:12Z",
  "actor": "user:1024",
  "tenant": "t-77",
  "sourceIp": "203.0.113.7",
  "action": "order.refund",
  "target": "order:5531",
  "result": "denied",
  "requestId": "9f2c1e"
}
```

**来源：** OWASP ASVS、OWASP 日志速查表、OWASP 多租户安全速查表

### 审计日志和运行日志分开 【推荐】

两者的用途、保存期限和访问人员不同，分开存储。

**来源：** OWASP 日志速查表、OWASP ASVS

### 业务账号不能修改审计日志 【必须】

只允许追加，比如只写的数据库账号或追加型表。到期删除由保留策略执行，见 [隐私](privacy.md)。读取权限受限。

**来源：** OWASP Top 10、OWASP 日志速查表、OWASP ASVS

### 可疑行为要告警 【推荐】

只记录不告警等于没有发现。为登录失败激增、大量授权失败、异常导出配置告警，控制误报。

**来源：** OWASP Top 10

## 限流

**适用：** 线上服务（本节全部规则）

### 高成本接口单独限流 【必须】

登录、验证码校验、短信、邮件、密码找回、导出、搜索这类接口，按业务设置更严格的阈值，不只用全局限流。同一操作的单用户频率也要限制。

| 接口 | 限流维度 |
|---|---|
| 登录 | 账号、IP、设备 |
| 发送短信 | 手机号、账号、IP，并设全局上限 |
| 校验验证码 | 单个验证码的尝试次数 |
| 导出 | 账号、租户、并发数 |

**来源：** OWASP API Security Top 10

### 安全相关的限流计数放在共享存储 【必须】

登录、短信、导出这类阈值精度影响安全或费用的接口，多实例部署时计数放在 Redis 这类共享存储，否则实际阈值会随实例数放大。超限时返回 429，并带 `Retry-After`。

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 30
```

### 正确获取客户端 IP 【必须】

只信任已知代理写入的转发头，在网关覆盖外部传入的值。否则攻击者每次换一个 `X-Forwarded-For` 就能绕过 IP 限流。

**来源：** OWASP ASVS

### 限制资源消耗 【必须】

| 资源 | 限制 |
|---|---|
| 请求 | 请求体大小、字符串长度、数组元素数 |
| 查询 | 分页上限，查询复杂度和深度 |
| 连接 | 读取超时、绝对超时，防慢速攻击 |
| 进程 | 内存、CPU、文件描述符 |
| 第三方 | 消费上限或账单告警 |

分页大小在服务端校验上限，不采用客户端传来的任意值。多租户系统按租户计量。超时和熔断见 [弹性设计](../reliability/resilience.md)。

**原因：** 单个请求就可能耗尽资源，短信和云服务还会产生直接费用。

**来源：** OWASP API Security Top 10、OWASP 拒绝服务速查表、OWASP 多租户安全速查表

## 防刷

**适用：** 线上服务（本节全部规则）

### 识别敏感业务流程 【推荐】

列出被过度使用时会伤害业务的流程，比如注册、领券、抢购、发帖、发短信。这类滥用的每个请求都合法，靠接口校验发现不了。

**来源：** OWASP API Security Top 10

### 业务限额在服务端强制 【必须】

单用户和全局的限额都要定义并执行。数量有限的资源用事务或锁防止超卖，同一权益防止并发重复领取。

**来源：** OWASP ASVS

### 分层减缓自动化 【推荐】

按风险组合使用：设备指纹、人机验证、非人类行为分析（比如一秒内完成加购和下单）、代理和 Tor 出口的 IP 情报。撞库工具会轮换代理，封禁决策不用单一阈值，并考虑共享出口的正常用户。这些手段只抬高成本，不作为唯一防线。B2B 和开放 API 同样要保护。

**来源：** OWASP API Security Top 10、OWASP 撞库防护速查表

## 账号风控

**适用：** 高风险（本节全部规则）

### MFA 是防撞库的主要手段 【必须】

风险高的登录要求 MFA，比如新设备、异地、已知泄露密码。设置密码和登录时检查是否在泄露库中。认证规则见 [认证](authentication.md)。

**来源：** OWASP 撞库防护速查表、OWASP ASVS

### 失败计数绑定账号 【必须】

失败次数按账号计，不只按 IP 计。连续失败上限不超过 100 次，业务可设更低，并用递增延迟或临时锁定。锁定期间保留用户自助恢复的路径，防止攻击者用反复失败锁定别人的账号。

**原因：** 只按 IP 计时，代理池可以轻松绕过。

**来源：** OWASP 认证速查表、NIST SP 800-63B

### 高风险操作重新验证 【必须】

改绑、提现、导出全部数据之前，要求再次认证或追加验证。

**来源：** OWASP ASVS
