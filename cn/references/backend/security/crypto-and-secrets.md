# 加密与密钥

本文讲算法选型、密钥管理、TLS 和字段加密。密码存储是单独的问题，见 [认证](authentication.md)。安全随机数的具体 API 见 `languages/<语言>/security.md`。配置的加载方式见 [配置](../architecture/configuration.md)。

## 算法选型

### 使用成熟的实现和算法 【必须】

用维护中的加密库，不自己实现算法和协议。按下表选型。

| 用途 | 使用 | 禁用 |
|---|---|---|
| 对称加密 | AES-256-GCM、ChaCha20-Poly1305 | ECB、DES、RC4 |
| 哈希 | SHA-256 及以上、BLAKE2 | MD5、SHA-1 |
| 消息认证 | HMAC-SHA-256 | 自行拼接的哈希 |
| 签名 | Ed25519、ECDSA P-256 及以上、RSA 3072 位及以上 | RSA 密钥短于 2048 位 |
| 公钥加密 | HPKE，或 RSA-OAEP | RSA PKCS#1 v1.5 加密 |
| 密钥派生 | HKDF，口令派生用密码哈希算法 | 基于 MD5 或 SHA-1 的 KDF |

**原因：** 算法本身安全不等于实现安全，自研实现很难避开侧信道和误用问题。

**来源：** OWASP 加密存储速查表、OWASP ASVS

### 用认证加密 【必须】

优先用 GCM 这类认证模式。只能用 CTR 或 CBC 时，必须另加 MAC，并采用先加密后 MAC。解密失败不向外区分原因。

**原因：** 只加密不认证的数据可以被篡改，错误差异还会形成填充预言攻击。

**来源：** OWASP 加密存储速查表、OWASP ASVS

### Nonce 不能重复 【必须】

同一密钥下，IV 和 Nonce 不重复使用。GCM 的 Nonce 重复会同时破坏机密性和完整性。达到所选模式的使用上限之前轮换密钥。

**来源：** OWASP ASVS、OWASP 加密存储速查表

### 安全随机值用 CSPRNG 【必须】

令牌、密钥、IV、会话 ID 这类不可猜测的值，用 CSPRNG 生成，至少 128 位熵。不用普通随机数，不把 UUID 当安全令牌。

**来源：** OWASP 加密存储速查表、OWASP ASVS

### 比对秘密值用常量时间比较 【必须】

**适用：** 高风险

比对签名、MAC 和令牌时用常量时间比较，不用会提前返回的普通字符串比较。

**来源：** OWASP ASVS

## 密钥管理

### 秘密不进入代码、镜像和日志 【必须】

密钥、令牌、数据库口令放在密钥管理服务中，或由平台安全注入。不写入代码、镜像层、构建参数、日志、错误信息和 URL。环境变量可以用于注入，但注意它容易被进程信息和崩溃转储暴露。

反例：

```yaml
env:
  DB_PASSWORD: s3cr3t-value
```

正例：

```yaml
env:
  - name: DB_PASSWORD
    valueFrom:
      secretKeyRef:
        name: orders-db
        key: password
```

**工具：** gitleaks、trufflehog，在提交钩子和 CI 中运行。

**来源：** OWASP 机密管理速查表、OWASP 加密存储速查表

### 秘密泄露后先吊销 【必须】

已进入 Git 历史的秘密视为泄露。先吊销或轮换，再清理历史，只删除提交不算解决。

### 密钥与数据分开存放 【必须】

**适用：** 高风险

密钥不和被保护的数据放在同一存储中。用信封加密时，DEK 加密数据，KEK 加密 DEK，KEK 放在 KMS 或 HSM 中，加密后的 DEK 可以和数据放在一起。

**来源：** OWASP 加密存储速查表

### 一个密钥只用于一个用途 【必须】

**适用：** 高风险

加密、签名、认证用不同密钥，不同环境用不同密钥，风险模型要求时按租户分开。密钥随机生成，不用单词或短语。

**来源：** OWASP 密钥管理速查表、OWASP 加密存储速查表

### 轮换流程提前准备好 【必须】

**适用：** 高风险

以下情况要轮换：怀疑泄露，有权限的人员离开，到达密钥有效期，接近模式的使用上限，算法出现新攻击。轮换方式在需要之前就绪。优先用动态、短期的凭证，减少人工轮换。用户密码不在此列，只在有泄露迹象时修改。

**原因：** 泄露发生时才开始写轮换流程，暴露窗口会被拉长。

**来源：** OWASP 加密存储速查表、OWASP 机密管理速查表

### 密文记录所用的密钥 【推荐】

每条密文保存密钥 ID。轮换后新数据用新密钥。轮换 KEK 时，用新 KEK 重新包装 DEK，再销毁旧 KEK。

**来源：** OWASP 加密存储速查表、OWASP 密钥管理速查表

## TLS

### 全链路使用 TLS 【必须】

**适用：** 线上服务

对外接口和跨主机的内部链路都加密，包括数据库、缓存、消息和监控，不退回明文。面向浏览器的入口把 HTTP 跳转到 HTTPS，并配置 HSTS，见 [Web 风险](web-risks.md)。API 不做透明跳转，直接拒绝明文。

**来源：** OWASP ASVS、OWASP TLS 速查表

### 只启用强协议和套件 【必须】

默认 TLS 1.3，最低 TLS 1.2。禁用 TLS 1.0、1.1 和 SSL。TLS 1.2 优先用 ECDHE 加 AEAD 的套件。

```nginx
ssl_protocols TLSv1.2 TLSv1.3;
```

**工具：** testssl.sh

**来源：** OWASP TLS 速查表、OWASP ASVS

### 客户端不关闭证书校验 【必须】

任何环境都不关闭证书和主机名校验。对外服务用公信证书。内部 CA 或自签证书只信任指定的 CA。

**原因：** 关闭校验后，TLS 无法防止中间人攻击。

**来源：** OWASP ASVS

### mTLS 校验证书后才信任身份 【必须】

用客户端证书的身份做认证或授权之前，先验证证书可信。

**来源：** OWASP ASVS

## 字段加密

### 按威胁模型选加密层级 【推荐】

| 层级 | 能防 | 不能防 |
|---|---|---|
| 磁盘或文件系统 | 物理介质失窃 | 应用或数据库被入侵 |
| 数据库透明加密 | 数据文件和备份被拷走 | 能查询数据库的账号 |
| 应用层字段加密 | 数据库账号、DBA、备份泄露 | 应用本身被入侵 |

最好的保护是不存储。能不存的敏感字段就不存，比如只保留令牌的哈希或银行卡后四位。

**来源：** OWASP 加密存储速查表

### 敏感字段在应用层加密 【推荐】

证件号、银行账户这类高敏感字段，用认证加密和信封加密处理，密文中带上密钥 ID。可以把记录 ID 作为附加认证数据，防止密文被挪到其他行。

### 加密字段的查询用盲索引 【推荐】

等值查询用带密钥的 HMAC 生成单独的索引列，不用确定性加密或无密钥哈希。盲索引仍会暴露“两行值相同”，低基数字段不适用。

**原因：** 手机号这类值空间很小，无密钥哈希可以被枚举还原。
