# 性能方法

本文讲通用方法。具体手段见前端和后端的性能文件。通用问题先调研成熟库，见 [dependencies.md](dependencies.md) 的“通用问题优先用成熟库”。

### 先测量 【必须】

没有数据不做性能优化。先找到真实瓶颈。避免 N+1 查询、重复请求这类已知反模式不需要先测量。

**来源：** 团队

### 前后用同一方法测 【必须】

改之前和改之后使用同一环境、同一数据量和同一步骤，否则结果没有可比性。

**记录内容：**

| 项目 | 示例 |
|---|---|
| 场景 | 打开一个大文件 |
| 环境 | 机器、版本、网络 |
| 方法 | 工具和步骤 |
| 次数 | 重复次数和统计方式 |
| 结果 | 优化前后的数字 |

**来源：** 团队

### 用分布看结果 【推荐】

除平均值外，还要看 P95、P99。平均值会掩盖少量极慢的请求。

### 优化要值得 【推荐】

优化带来的复杂度要和实际收益相称。收益不明显时，保留简单实现。

### 优先改结构 【推荐】

减少不必要的工作，比如重复请求和多余计算，通常比微调代码更有效。

### 报告实际数字 【推荐】

汇报时写明优化前后的数字和测量方法，不只说“更快了”。
